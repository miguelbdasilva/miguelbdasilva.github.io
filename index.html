CONFIGURAR A REDE

Este é o passo mais crítico. A VM precisa de dois adaptadores de rede: um para internet e outro para comunicação com seu PC. A ordem importa — Adaptador 1 = NAT, Adaptador 2 = Host-only.

03
Ubuntu

CONFIGURAR O UBUNTU

Ligue a VM. O Ubuntu instala automaticamente (instalação desassistida). Aguarde o prompt de login — pode demorar 5–10 minutos. Faça login com ubuntu / ubuntu.

Passo 3.1 — Configurar o teclado para PT-BR

Por padrão o Ubuntu vem com layout de teclado americano (US). Antes de digitar qualquer comando, configure para ABNT2 para evitar problemas com caracteres como :, @ e -:

bash — na janela da VM
sudo dpkg-reconfigure keyboard-configuration

Vai abrir um menu azul. Navegue com as setas e selecione:

Tela 1 — Modelo
Generic 105-key PC
Tela 2 — País
Portuguese (Brazil)
Tela 3 — Layout
Portuguese (Brazil)
Tela 4 — AltGr
The default for the keyboard layout
Tela 5 — Compose key
No compose key

Depois aplique sem precisar reiniciar:

bash
sudo setupcon
Dica Após esse passo, o teclado já fica em ABNT2 permanentemente — inclusive após reboots. Teste digitando : e @ para confirmar.

Passo 3.2 — Atualizar o sistema

bash — na janela da VM
sudo apt update && sudo apt upgrade -y

Se aparecer a tela roxa "Which services should be restarted?" — pressione Enter para aceitar e continuar.

Passo 3.3 — Tornar a interface Host-only permanente

Por padrão, a interface Host-only (enp0s8) não sobe automaticamente após o reboot. Corrigimos isso editando o Netplan — o gerenciador de rede do Ubuntu.

Primeiro veja os nomes exatos das interfaces:

bash
ip link show

Você verá enp0s3 (NAT) e enp0s8 (Host-only). Agora edite o arquivo de rede:

bash
sudo nano /etc/netplan/00-installer-config.yaml

Substitua todo o conteúdo por:

/etc/netplan/00-installer-config.yaml
network: version: 2 ethernets: enp0s3: dhcp4: true enp0s8: dhcp4: true

Salve: Ctrl+O → Enter → Ctrl+X. Depois aplique:

bash
sudo netplan apply

Passo 3.4 — Corrigir o DNS permanentemente

bash
sudo sed -i "s/#DNS=/DNS=8.8.8.8/" /etc/systemd/resolved.conf && sudo systemctl restart systemd-resolved

Passo 3.5 — Verificar IPs e testar internet

bash
ip a

Anote o IP da enp0s8 — será algo como 192.168.56.104. Você vai usar esse IP para SSH e para acessar o dashboard.

bash
ping 8.8.8.8 -c 3
Resultado esperado 3 packets transmitted, 3 received, 0% packet loss
04
SSH

ATIVAR ACESSO SSH

Com SSH ativo, você acessa a VM pelo PowerShell do Windows e consegue colar comandos longos normalmente com Ctrl+V — sem problema de layout de teclado.

Passo 4.1 — Instalar o servidor SSH

bash — na janela da VM
sudo apt install openssh-server -y

Passo 4.2 — Conectar pelo PowerShell do Windows

Abra o PowerShell no Windows. Substitua o IP pelo que você anotou no passo 3.4:

PowerShell (Windows)
ssh ubuntu@192.168.56.104

Na primeira conexão, digite yes quando perguntar sobre o fingerprint. Insira a senha ubuntu.

Resultado esperado ubuntu@Wazuh-Server:~$
A partir daqui: use o PowerShell via SSH Todo o restante do guia deve ser executado no PowerShell conectado via SSH, não na janela da VM. Isso permite colar comandos sem problema.
05
Wazuh

INSTALAR O WAZUH

O Wazuh será instalado no modo all-in-one: um único script instala e configura todos os componentes automaticamente.

Componentes instalados

  • →
    Wazuh Indexer — armazena e indexa alertas (baseado em OpenSearch)
  • →
    Wazuh Manager — recebe logs dos agentes e gera os alertas
  • →
    Filebeat — encaminha alertas do Manager para o Indexer
  • →
    Wazuh Dashboard — interface web para visualizar e investigar alertas

Passo 5.1 — Instalar o curl

O curl é necessário para baixar o script de instalação do Wazuh. Verifique se já está instalado e instale caso não esteja:

bash — via SSH no PowerShell
sudo apt install curl -y
Resultado esperado curl is already the newest version (...) — ou instalação concluída sem erros.

Passo 5.2 — Executar o script de instalação

bash — via SSH no PowerShell · demora 10–15 min
curl -sO https://packages.wazuh.com/4.7/wazuh-install.sh && sudo bash wazuh-install.sh -a
⚠ Anote as credenciais ao final O script exibe usuário e senha do dashboard apenas uma vez, ao terminar. Não feche o terminal antes de copiar.
Saída ao final da instalação INFO: You can access the web interface https://<ip>:443
    User: admin
    Password: [senha gerada automaticamente]
INFO: Installation finished.

Se precisar recuperar a senha depois:

bash — recuperar senha
sudo tar -O -xvf wazuh-install-files.tar wazuh-install-files/wazuh-passwords.txt

Passo 5.3 — Acessar o dashboard

No navegador do seu Windows, acesse (use o IP da enp0s8 que você anotou):

URL
https://192.168.56.104
Aviso de certificado O navegador vai alertar sobre certificado não confiável — é normal. Clique em Avançado → Continuar assim mesmo. O certificado é autoassinado pelo próprio Wazuh.

Faça login com admin e a senha gerada. O dashboard vai aparecer com "No agents were added to this manager."

06
Windows

INSTALAR O AGENTE WINDOWS

O agente Wazuh é instalado no Windows e envia os logs do sistema para o servidor. Vamos instalar na própria máquina Windows.

⚠ Se o agente já foi instalado antes — desinstale primeiro Se você já instalou o agente Wazuh em algum momento anterior, é necessário removê-lo completamente antes de reinstalar. Pular esse passo causa conflito de registro.

Passo 6.1 — (Apenas se reinstalando) Desinstalar o agente anterior

Abra o PowerShell como Administrador e rode:

PowerShell Admin (Windows) — desinstalar agente
wmic product where "name like 'Wazuh Agent%%'" call uninstall

Aguarde a conclusão. Depois verifique se foi removido com sucesso:

PowerShell Admin (Windows) — verificar remoção
Get-Service WazuhSvc
Resultado esperado — desinstalação confirmada Get-Service : Cannot find any service with service name 'WazuhSvc'
← Esse erro é o resultado correto. Significa que o serviço não existe mais.
Se o serviço ainda aparecer Reinicie o Windows e tente o comando de desinstalação novamente antes de prosseguir.

Passo 6.2 — Gerar o comando pelo dashboard

No dashboard, clique no aviso amarelo Add agent. Configure:

  • 1
    Package: Windows → MSI 32/64 bits
  • 2
    Server address: 192.168.56.104 (IP da sua VM)
  • 3
    O dashboard gera o comando completo na seção 4 — copie ele

Passo 6.3 — Instalar o agente (PowerShell Admin)

Abra um novo PowerShell como Administrador no Windows. Cole o comando gerado pelo dashboard — o formato é este:

PowerShell Admin (Windows)
Invoke-WebRequest -Uri https://packages.wazuh.com/4.x/windows/wazuh-agent-4.7.5-1.msi -OutFile ${env.tmp}\wazuh-agent; msiexec.exe /i ${env.tmp}\wazuh-agent /q WAZUH_MANAGER='192.168.56.104' WAZUH_REGISTRATION_SERVER='192.168.56.104'

Passo 6.4 — Iniciar o serviço

PowerShell Admin (Windows)
NET START WazuhSvc
Resultado esperado O serviço de Wazuh foi iniciado com êxito.

Passo 6.5 — Confirmar no dashboard

Volte ao dashboard e clique em Refresh. O contador Active agents deve mostrar 1 e o nome do seu PC deve aparecer na lista.

07
SOC · Blue Team

SIMULAR ATAQUE E INVESTIGAR

Com o agente ativo, vamos simular atividade maliciosa no Windows para gerar alertas reais no SIEM e praticar a análise como um analista SOC N1.

Passo 7.1 — Simular brute force de conta

PowerShell Admin (Windows) — simulação segura
for ($i=1; $i -le 10; $i++) { net user administrador senhaerrada$i }
Por que esse comando gera alertas? O net user tenta modificar a conta "administrador" repetidamente. O Windows registra isso como Event ID 4738 (User Account Changed). O Wazuh detecta e classifica como potencial manipulação de conta — técnica T1098 do framework MITRE ATT&CK.

Passo 7.2 — Ver os alertas

No dashboard: Security Events → aba Events. Mude o período para Last 15 minutes e clique em Refresh.

Alertas esperados Rule: User account changed · Rule ID: 60110 · Level: 8
MITRE: Account Manipulation · Valid Accounts · Create Account
